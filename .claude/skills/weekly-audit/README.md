# weekly-waste: the weekly waste report, records only

The owner's decision D19 (13 October 2026) chose a records-only weekly report, as amended by the design review CR-WASTE-B. Its purpose, in that review's words: "The weekly report shows recorded helper consumption and recorded operational outcomes across runs, so the Sunday review can identify concentrations and possible recurrence. It does not measure avoidable time or certify that a week contained no waste. Fine-grained diagnosis remains in each run's own evidence."

The report prints no clean or waste-free verdict. The Sunday judgement stays with the owner and the head.

| `FIELDS.md` | the field-to-figure contract: every field each figure reads or the report renders, its writer and line, the record formats in the store, units, aggregation, and how ordinary, resumed, interrupted and historical records are handled |

## What it reads and writes

- **Reads** the run records in `<store>/spawn-records/`, the store being `LLM_WIKI_STORE` or `~/.llm-wiki` as `handsoff.py` resolves it (`--records DIR` overrides), and its own `dispositions.jsonl`. Nothing else is read. No session transcript, GPT-6 Astra event log, helper report, brief or prompt is read, no path outside the records folder is opened, and no subprocess is started.
- **Admits run records under the owner's input contract**, decision B17 of 14 October 2026 (spec-D19.md, "Input contract (the owner's decision B17, 14 October 2026)"; FIELDS.md, "Admission"). Its text: "For the weekly report, the run-record inputs are every direct `.jsonl` file in the records folder except the five historical event-log names explicitly listed in the input contract. The reader acquires those records independently and never follows references to obtain further inputs. An admitted record remains an input when another record names it as evidence; that reference alone is neither a prohibited read nor incomplete figure coverage. Excluded evidence files remain unopened, including through subprocesses. Producers must keep evidence outside the admitted namespace. This contract relies on that separation and does not promise to detect misfiled evidence before opening it." The reader decides for every `*.jsonl` in the folder, by its name alone, before it opens any file:
  - admitted: every `*.jsonl` file directly in the records folder, whatever its run id (attended and hand-written records, ids without the `run-` prefix and ids containing `-events-` included);
  - not admitted: the five historical event logs pinned by exact name, `run-20260909-n14-accept-events-L1.jsonl`, `-L2`, `-L3`, `-L5` and `-L6`. Each is never opened; each report lists it by name in its coverage section, its contents unread and unknown, and no figure reads it;
  - not admitted, by the owner's extension of the contract (approved on 25 October 2026) beside the five names it lists: the command checker's read logs, `<run>-unplaced-reads.jsonl` with `<run>` a run id beside its run's record `<run>.jsonl`, which lane-fence.py's read logging appends to in the records folder, their lines holding no event name. Each is left out by its name, never opened, and listed in the same coverage line and in the inventory; a name of that form with no `<run>.jsonl` beside it is a run record like any other, and so is one whose prefix is no run id (FIELDS.md, "Admission");
  - never opened: any other extension, any path outside the folder (a subfolder's files included), and a candidate that is a symbolic link (never followed) or not a regular file (named unreadable, a gap of its run's figures);
  - a reference is never followed: a record that another record names as evidence, in any field and any spelling, is read once, as a run record like any other. A file outside the inputs that a record names is never opened, whatever it holds;
  - what a reference may and may not change (spec-D19.md, "Input contract", the bullet of that name): a reference, and an excluded file named by one, change no figure, no coverage status and no other substantive report content; the acquisition time, the measured byte counts and the folder inventory (each file's own listing line) are reported as they are, so adding or removing a reference field, or removing an excluded file inside the folder, changes those lines and nothing else.
- **Links** each run's own waste table, `<store>/spawn-records/<run>-waste-table.md` (`--tables-dir` overrides the folder), by path, when a stat finds it. The table is never opened, parsed or regenerated.
- **Writes** three things and nothing else:
  - `output/reports/waste-detail-<until>.md`, through a temporary file and a rename;
  - one append of this report's lines to `dispositions.jsonl`;
  - `output/reports/waste-report-<until>.md`, through a temporary file and a rename, last.
- A report re-run for the same interval replaces both files. The store keeps every run's lines.

## The figures

Each figure is defined in CR-WASTE-B's words in the specification, and its fields are in FIELDS.md. In brief:

| Figure | Reads | Shows |
|---|---|---|
| Helper time | `lane-closed.duration_s`, by run, class and helper | recorded execution seconds of the episodes closing in the interval; the three views reconcile; concurrent durations add as consumption |
| Failed closes | `lane-closed.exit_class` | closes by recorded exit status, non-completed shown apart, and those later resumed; no lost-work verdict |
| Review activity and possible loops | the class (critic, verifier, gate-judge) and the `gate` before the opening (`item`, `decision`, `ts`) | reviewing-class episodes (by class alone, not evidence of review); evidenced item associations (none recorded); positional candidate groups (episodes after one allowed, dated gate with no gate inside their span), those with no group, and groups of two or more as a cue for the walk-through; rounds always unresolved |
| Phase boundaries | `phase-boundary.idle_min` by `idle_src`, `over_cap_reports`, `rewrites`; `rewrites_total` as a dated snapshot | the boundaries' own recorded figures at their own timestamps; sources and cumulative values never summed together |
| Refusals | `lane-closed.denials` (tool, fence, sandbox) and `sandbox_denials`; `phase-boundary.head_denials` and `denials` | helper refusals by channel, the head fence apart, the boundary's helper summary never added again |
| Priced spend | `cost_src`, `total_cost_usd`, `session_id` and `lane`; a close's `usage.modelUsage` (each model's cost and four token counts); a beat's `usage.models` and four aggregate token counts; GPT-6 Astra `usage` and `usage_state`; the snapshots `run_spend_usd`, `spend_usd`, `head-exit.spent_usd` | priced dollars on the Claude CLI's own basis, each session once, after validating its whole history before the exclusive end: running totals count the last total less the last before the start, per-pass costs sum the interval's passes, and one valid line counts its amount. Any lost, unusable, contradictory or inconclusive evidence leaves dependent spend unknown with a named gap; empty or incomplete inventories cannot prove a dropped model, and a priced close's inventory is incomplete when its model costs miss its total by more than 1E-9 USD (FIELDS.md, "Priced spend": the head's decision of 27 October 2026). Beat evidence can establish per-pass costs or contradict running totals. Plan usage remains separate by state and token direction; unpriced and not-applicable closes remain separate; run and head totals are dated snapshots, never added |

Every value is a measured zero, known, not applicable, unknown or invalid, and an invalid value stays invalid. A total is complete only when every input it declares is available. Otherwise it reads `unknown; known subtotal X`, in the main report and in the detail alike, and each missing input is named in the detail with the parts it affects. A gap counts only against the parts, runs, helpers, classes, idle sources and spend bases its input could feed, so a damaged record or line leaves an independent source's totals known: an undated close of a known non-review class leaves the reviewing-class counts complete; a boundary of a known source without its idle minutes leaves the other sources' sums complete; a result-priced beat without a price leaves the count of beats not priced complete. A GPT-6 Astra close keeps the accounting state its writer recorded (an `incomplete` close stays incomplete), and each token direction is read on its own: absent or null is unknown, another kind invalid, and the other direction stays known. A missing field never becomes zero. "Not applicable" is used only for a spawn failure (no process started: for the fields the close does not record; a `sandbox_denials` it does record is read as recorded), a transcript-estimate close (no dollar figure, by design), plan usage (never priced) and a plain run's close (its own `spend_usd`; a run-close's `shape` other than the writer's is invalid, never read as the ordinary close). A reference from one record to another changes no value, no status and no coverage label. FIELDS.md's "Field and state coverage" names, for every consumed field and each of its states, the cases that fix it.

Expected invalid record content is named; unexpected exceptions use the containment rules below, subject to the stated runtime and I/O limits (FIELDS.md, "Unexpected-failure containment"). A number in any field a figure sums, rounds or renders is read only within the reader's range, a magnitude below 10^15 and at most 30 decimal places; any other is invalid and named, its total unknown with the known subtotal kept. A line holding a number the decimal library cannot represent, or a string with an unpaired surrogate, is named not JSON. A timestamp whose fraction of a second runs past nine digits is no usable time; an accepted one is rendered to its last digit. No recorded string is read as one of the reader's labels: whether a value is uncertain travels in a field of its own, and a recorded string that could read as a label is shown quoted, so a class "(builder)" is a class like any other, shown `'(builder)'`, beside the real `(class unrecorded)`, and a record `all.jsonl` is the run `all`, apart from each view's total row, `(all)` (FIELDS.md, "Recorded strings and the reader's labels"). No recorded value starts a line of either report: a line break it holds is shown as `\n`. No identity is read back out of a string built from recorded values (FIELDS.md, "Identities, never strings read back"). Every sum of recorded decimals is exact, and a figure is rounded once, where it is displayed: prices of $0.025 and $1e-30 total $0.03.

## Scope and coverage

- Each report states its interval as `[start, end)` in local time with the zone, and its acquisition window. Episodes count wholly at their close and boundary events at their own timestamps.
- Every candidate record is inventoried in the detail, including records without `run-open` and records outside the interval. Every pinned event log and command checker's read log present is listed by name in the main report's coverage section and in the detail's inventory, unopened; the folder's other entries are counted.
- Every record holding an unreadable, malformed or undated line is named in every report until it is mended. An undated line reaches only the intervals between its dated neighbours when the record's dated lines are in order, and every interval otherwise.
- Every episode still open at acquisition is named, however old, including one opened after the interval's end. So is every **unresolved** episode: one whose close has no usable timestamp, since a malformed close is not evidence that the opening resolved.
- Hand-written and early episode lines under historical names (`lane-resume`, `lane-close`, `spawn`, `close-out`, `probe-open`, `probe-closed`) are read by the compatibility rule in FIELDS.md. `terminated`, `stalled` and `lane-aborted` are end markers, noted on their episode, never a close. Every such line is listed in each detail.
- An empty or inaccessible records folder is a failed premise (exit 2), never a clean week.
- Completeness refers only to these record inputs: it cannot establish that an unrecorded run never existed. Report generation succeeding is not evidence of completeness.
- The main report gives runtime and input volume. The head's reading cost is labelled unmeasured until observed.

## The dispositions store

`dispositions.jsonl` in `<store>/tools/weekly-waste/` (`--tools-dir` names another folder) is the one authority for dispositions and determinations. It holds one JSON object per line, in the held design's line format (its README, "The dispositions store"): every kind and field of that format, which the reader reads as that format writes it, plus what the reader adds to the lines it writes itself: the `at` of the report, listed and disposition lines; the `record_lines` and the structured identity (`record`, `helper`, `line`) of an abandoned line; and the `run-ended` kind of the held design's item 8, with its `record`.

| `kind` | Written by | Fields |
|---|---|---|
| `init` | `init`, once | `at`, `version` |
| `report` | each report | `interval` [start, end], `report`, `detail`, `at`, `listed`, `not_seen` |
| `listed` | each report, one per key | `key` (`<figure>@<interval>`, `coverage@…` when gaps are named, `store-continuity@…` when the store is malformed), `class`, `name`, `interval`, `at` |
| `disposition` | `dispose` | `key`, `disposition` (fixed, registered, kept or owner), `note`, `at` |
| `abandoned` | `abandon` | `episode`, `evidence`, `at`, `last_event`, `record_last_event` (the held format); the reader's own also `record`, `helper`, `line` and `record_lines` |
| `run-ended` | `end-run` | `run`, `record`, `evidence`, `at`, `record_last_event`, `record_lines` |

- A report lists one key per figure for its interval, so the Sunday review disposes of each figure's reading. Keys left open reappear in the next report. Each report also lists the dispositions recorded since the previous report.
- A missing or unreadable store is never recreated: the report is written, opens with the continuity failure, records no line, and exits 1. A malformed store still receives the report's lines, and its `store-continuity` key stays open until disposed. A store line that cannot be read (not JSON, nested past the interpreter's depth, or holding a string with an unpaired surrogate) makes the store malformed and is named, never an abort. `init` never overwrites a store.
- `dispose KEY DISPOSITION --note TEXT` refuses, writing nothing, a key the store does not list (it names the nearest), an empty note, an unknown disposition and a missing or unreadable store.
- `abandon <record>:<helper>:<line> --evidence TEXT [--record NAME --helper NAME --line N]` records that an open episode can never resolve (its helper's process gone), with its record's extent then: its line count and its last event, to the fraction of a second. The episode is its record, helper and opening line; the string names it as the report's detail does, and a record or a helper may hold ":", so the string is read every way it can be. Where it could name more than one opening (`r:x:y:1` is `r.jsonl`'s helper `x:y` and `r:x.jsonl`'s helper `y`), the detail shows each one's record, helper and line beside its key, and `abandon` refuses the string alone; `--record` (the file name), `--helper` and `--line` name the one meant, and must spell the same string. The line written carries that identity beside the string, so no report reads it as another opening. Reports whose interval begins after it leave the episode out of the open list. Earlier reports keep it named, incomplete and with unknown duration. Any later event on its record voids it, one with the same timestamp included, and every report lists it with its effect and evidence. It refuses, writing nothing, an empty evidence, a string that could name several openings, a key it cannot find, a record named in another case or form than the folder lists it, a closed or unresolved episode, a record with an invalid or undated line, and a missing or unreadable store. Age alone is never closure.
- A determination already in the store in the held format, its string alone, applies where that string names exactly one opening of the admitted records, and to none where it could name more (each listed as ambiguous, with the openings it could name). A held-format line has no line count of its record, so it is checked by its last event (an instant, whatever its offset form) and the record's validity, and its effect names what that leaves unchecked: an event added later at or before that last event (the same second, or out of order) cannot be seen.
- `end-run RUN --evidence TEXT` records that a run's head has ended, with the record's name beside the run. Reports whose interval begins after it list the run as ended rather than open. Any change to the record voids it. It refuses a record without `run-open`, a closed run, an invalid record, a name the folder does not list exactly and a missing store. In this records-only report it changes no figure.

## Arguments and exit codes

| Argument | Meaning | Default |
|---|---|---|
| `--until YYYY-MM-DD` | the interval ends at 00:00 local time that day | today |
| `--since YYYY-MM-DD[THH:MM]` | the interval's start | the end of the latest earlier report in the store, else seven days before `--until` |
| `--records DIR` | the run records | `<store>/spawn-records` |
| `--tools-dir DIR` | the folder holding `dispositions.jsonl` and `reports/` | the store in `<store>/tools/weekly-waste/`, the reports in the vault's `output/reports/` |
| `--tables-dir DIR` | where the per-run waste tables are looked for | the records folder |

Exit 0: the detail and the report were written and the store lines appended. Exit 1: both were written but the store is missing, unreadable or malformed. Exit 2: a bad argument or a broken premise (no records folder, no candidate record, no admitted record, no `reports/`, an empty interval, a local time that does not exist or repeats; for a subcommand, its refusal, a pinned event log, a name with a path in it or a symbolic link among them): `PROBE FAILED: …` on stderr and nothing written.

A report lists the `coverage@…` key when it names a gap.

## Install

The files ship in this skill folder, so there is nothing to copy. `setup.sh` runs step 1 on a fresh vault; there is no other installer.

1. Make its folder, `mkdir -p <store>/tools/weekly-waste`, then run `init` once: `python3 -B .claude/skills/weekly-audit/weekly-waste.py init`. This creates `<store>/tools/weekly-waste/dispositions.jsonl` (the first store; none exists yet) and the vault's `output/reports/`, and refuses if a store is already there.
2. Run the suite once, with a scratch TMPDIR: `TMPDIR=<scratch> python3 -B .claude/skills/weekly-audit/test_weekly_waste.py`. It must end `PASS n/n`.
3. The Sunday step stands in the Weekly review of `CALENDAR.md`, which `setup.sh` seeds: its own paragraph after the line on finishing the audit.
4. The script and the suite each take a row in `wiki/developments/check-lifecycle.md`, under "### Monitors" and "### Test suites", at the first audit that lists them as missing.

## How the Sunday review runs it

The owner starts his Sunday review; no scheduled job starts this report. In that session the head:

1. Runs `python3 -B .claude/skills/weekly-audit/weekly-waste.py` with no arguments. The interval runs from the previous report's end to 00:00 today. The report and its detail go to `output/reports/`.
2. Reads the main report whole, coverage first, and opens the detail only to judge a specific item.
3. Walks the owner through the concentrations and the possible recurrence the figures show: the top runs, classes and helpers by helper time, non-completed closes, positional candidate groups of reviewing-class episodes, refusals, spend and plan usage. Each judgement is the owner's and the head's; the report makes none.
4. Records each figure's disposition with `weekly-waste.py dispose <key> <fixed|registered|kept|owner> --note "<reason or blocker>"`. For an open episode whose helper has ended, it records `abandon <record>:<helper>:<line> --evidence "<what shows it>"`, adding `--record`, `--helper` and `--line` as the detail shows them where the key could name more than one opening. For a run whose head has ended, it records `end-run <run> --evidence "<what shows it>"`.

Exit 1 means the store's continuity broke: restore it from a copy, or mend the lines the report names, then dispose of its `store-continuity` key once it is listed. A record named as unreadable, undated or unresolved is mended or restored; nothing else removes it from the list.

## Undo

1. Remove `weekly-waste.py`, `FIELDS.md`, this file and `test_weekly_waste.py` from this folder, and `<store>/tools/weekly-waste/` with its store. Keep a copy of `dispositions.jsonl` first if its dispositions are still wanted. Reports already written to `output/reports/` stay as dated records.
2. Remove the Sunday step's paragraph from the Weekly review of `CALENDAR.md`.
3. For the two `check-lifecycle.md` rows: if the install is rolled back in the same pass, before any Sunday has run it, remove the two rows added, which leaves the file as it was. Otherwise mark them retired under that register's own rules: State `retired`, the reason in Retire when, the re-arm condition kept, Next review a dash.

Nothing else in the vault or the run store is written by the script, so nothing else needs undoing.

## Known limits

- No record carries an item or a round for an episode, so item-based totals are not computed and rounds stay unresolved. Positional groups are a cue, not an association.
- The review classes (critic, verifier, gate-judge) and the three top rows per helper-time view are set by judgement, unmeasured.
- The reader's range (a magnitude below 10^15, at most 30 decimal places) and the nine digits of a fraction of a second are set by judgement, unmeasured, with headroom over every value in the store when they were set (FIELDS.md, "The reader's range"). A writer that one day records a larger or finer value has it named invalid, never read, until the bound is reviewed.
- A lane.py close has no sandbox channel, so the helper sandbox total is unknown in any week with a Claude close. Its tool and fence channels are unaffected.
- An event name outside the known list (`KNOWN_EVENTS`: the writers' names and every name in the store at the build) makes its line invalid until the name is added.
- No line names the harness's version, and older records may report a resumed pass's own cost rather than its session's running total. Each session is read from its own complete evidence, including beats. If that evidence cannot distinguish the readings, or any relevant line is lost, unusable or contradictory, the priced spend is unknown with a named gap (FIELDS.md, "Priced spend"). A one-close/one-beat pair has no automatic reading.
- A determination in the held format has no line count of its record: an event added later at or before the record's last event then (the same second, or out of order) is not seen, and the report says so beside the determination. Lines the reader writes carry the count.
- A record or a helper holding ":" can make two episodes share a key. The detail then names each with its record, helper and line, and `abandon` needs `--record`, `--helper` and `--line` for it; a determination by the string alone applies to neither.
- Admission is by name under the owner's input contract (B17): every `*.jsonl` in the records folder is read as a run record except the five pinned event logs and the command checker's read logs (`<run>-unplaced-reads.jsonl` beside its run's record, the owner's extension approved on 25 October 2026). An evidence file given a `.jsonl` name there is read as a record (its lines most likely invalid and named): the contract relies on the producers keeping evidence outside that namespace and "does not promise to detect misfiled evidence before opening it". No writer rule yet keeps evidence out of it (the register entry for the writers).

## Unexpected-failure containment

The report command assigns each physical record/store line an identity before checking for a blank line. It commits validated kind and timestamp facts separately from the immutable decoded payload. One reusable boundary catches unexpected `Exception` subclasses, including `ValueError`, `NameError` and `AssertionError`. `Probe`, `Bad` and `NotOpened` escape that boundary; expected invalid values keep their existing validation handlers. `KeyboardInterrupt`, `SystemExit` and `GeneratorExit` escape. Both reports name every contained failure by physical source, route and exception class; exception messages and payload representations are excluded from this ledger.

A new failure discards the tentative generation, including its analysis, figures, coverage, helper views, determinations, keys, summaries and pending store lines. Replay starts from immutable acquired envelopes and accumulated uncertainty. A route/owner slot fails at most once; terminal slots bypass their callable. With K declared routes, L acquired physical line positions, R record anchors and one global anchor, at most K × (L + R + 1) slots can fail, followed by one successful preparation. This is a finite-input bound, not a time limit. The terminal emitter uses cached safe labels and fixed unknown text without calling ordinary row formatters. The suite observes unexpected catches independently of successful-looking reports through both invocation paths, and tests that observation with recorded and silent catch mutants.

Contained record failures use the conservative domain table in FIELDS.md. An episode failure withdraws all episode-derived contributions of its record, including plan/basis/token counts and earlier resumed status; an independent record survives. A boundary failure withdraws that record's boundary/refusal-summary/snapshot families while preserving episode consumption. Gates withdraw positional activity and spend snapshots; beats withdraw beat spend; trusted process markers open no episodes. Unknown kind or failed timestamp/metadata validation withdraws all figure families of that record. Containment gaps remain visible regardless of the source timestamp. Affected membership, ranking, coverage and determination eligibility are unknown; a surviving subtotal is not a complete total.

Store failures make continuity malformed and exit 1. Their authorities are separate: `report` makes default-start selection and chronology uncertain; `listed` makes carried-key inventory incomplete; `disposition` makes all relevant current and carried key statuses undetermined; `abandoned` makes episode exclusion uncertain; `run-ended` makes run-ending status uncertain; `init` affects continuity. An untrusted kind receives their union. Earlier or later winners cannot clear these flags in the same invocation. Successfully observed keys and record-established determination candidates remain visible.

Store-entry construction and publication share a physical-line boundary. A failed candidate publishes neither its entry nor its cached key, including a failure after the tentative assignment. The terminal combined-history path uses committed primitive key observations and current keys: every observed identity remains visible with membership and status uncertain, and the since-previous list says unknown.

Every contained failure adds a separate identity-observation section to both reports, including every committed listed identity and final current identity in an appended batch. This section makes no membership or disposition decision. Successfully prepared statuses and history retain the rules of their individual store authorities; only failed combined key preparation selects the unavailable-preparation fallback. An empty prepared history distinguishes uncertain chronology/dispositions from a known zero; an unrelated failure keeps that zero. Whole-report and encoding recovery retain prepared statuses and historical entries using terminal escaping. A failed individual history row names its unavailable presentation while other rows survive. Unresolved-start diagnostics and unavailable generation/outgoing preparation append nothing. The suite checks independent history, key retention and the explicit no-append alternatives across recovery routes.

Run candidates carry an explicit open or unknown state into both reports; a failed close cannot turn its earlier opening into a definite open run. Each positional review group owns the source of its first episode opening, with all group suppliers attributed separately, so another record's group survives a presentation failure. The table-link count is the number actually rendered in the final detail candidate; terminal link presentation names its unavailability.

Failed invalid-line presentation retains its physical locator with an unavailable status; failed inventory presentation cannot claim a clean section. Table selection has a separate availability flag: failed selection is unknown with zero rendered links, while a successful empty selection may report none found.

Without `--since`, uncertain report selection produces two diagnostic reports stating “start unresolved”; no interval computation, numeric subtotal, interval-dependent determination or ordinary interval key is evaluated, and no store line is appended. Repeating the default invocation cannot advance history. An explicit `--since` establishes a real interval while retaining the other authority uncertainties. A failed outgoing serialisation similarly suppresses the whole append batch, names persistence unavailability in both reports and exits 1. Missing/unreadable stores retain the no-recreation rule.

Both reports, stdout and every outgoing store line are formatted and encoded before publication. The commit order remains detail, append, main. This is not a multi-file filesystem transaction: write failure, interpreter termination, non-returning operations and resource exhaustion that prevents recovery are outside the completion guarantee.

## Exact endpoints and identity display

Default selection, interval membership, keys, labels and both stored endpoints retain the parsed rational timestamp. A fractional `:00.5` is never treated as a whole minute; equivalent offset spellings describe the same instant. CLI date syntax is unchanged.

An opening-line suffix must be canonical positive ASCII decimal no greater than `sys.maxsize`. An acquired bytes object cannot contain a physical line beyond its maximum addressable byte position; digit count and lexical comparison against that bound therefore precede integer conversion. The same parser serves store validation, identity lookup, legacy `abandon` and `--line`; a structured integer is range-checked without first converting it to text. Invalid CLI identities write nothing.

Every helper component is represented as a JSON string with ASCII escapes before table/line formatting. Newline, literal backslash-plus-n, space, quotes, pipes and Unicode separators retain distinct labels. Held episode keys are opaque quoted keys; ambiguous openings additionally show their structured identities. Stored keys and structured identities are unchanged.

Runtime is measured through preparation immediately before rendering the final candidate, including completed recovery generations. Publication I/O and the final rendering/encoding time are excluded; real-data evidence also records the full command wall time.
